## 주요 결정

| 결정 항목 | 결정 | 이유 |
|-----------|------|------|
| Risk grade 필터 방식 | 클라이언트 로컬 필터 대신 서버 필터 | 카드 집계와 목록 결과를 같은 기준으로 맞추기 위해 |
| Inventory 카드 기준 | 선택 월에 대응하는 월간 risk snapshot 사용 | 카드/KPI와 목록의 시점 정합성을 맞추기 위해 |
| Inventory 목록 안내 문구 | `현재 로드 / 필터 결과 / 조회 대상` 3단 분리 | 사용자가 200건이 전체라고 오해하지 않도록 하기 위해 |
| 성능 개선 1차 대응 | API 메모리 캐시 30초 TTL | 구조 개편 전 체감 속도를 낮추기 위한 단기 대응 |
| 성능 개선 다음 단계 | 월별 snapshot 집계 테이블 + RPC | 현재 병목을 가장 크게 줄일 수 있는 방향이기 때문 |
