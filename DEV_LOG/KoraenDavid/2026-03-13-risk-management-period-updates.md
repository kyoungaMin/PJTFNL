# 📋 개발 일지 (2026-03-13)

오늘 **리스크 관리 페이지**의 평가 구조를 주간/월간으로 이원화하고, 이에 따른 백엔드 API 고도화 및 UI 개선 작업을 완료했습니다.

---

## 🚀 1. 리스크 평가 구조 이원화 (주간/월간)
- **개요:** 리스크 점수 산출 주기를 주간과 월간으로 구분하여 사용자가 원하는 단위로 현황을 파악할 수 있도록 개선했습니다.
- **백엔드 고도화:**
  - `risk_score` 테이블의 `eval_type` ('weekly' | 'monthly') 컬럼을 필터링에 반영했습니다.
  - 관련 API 수정:
    - `/api/risk/filters`: 요청된 타입에 맞는 기준일 목록만 반환하도록 수정.
    - `/api/risk`: 선택된 타입과 날짜에 따른 리스크 목록 조회 기능 구현.
    - `/api/dashboard`, `/api/alerts`, `/api/forecast-weekly/risk-summary`: 시스템 일관성을 위해 기본 리스크 조회를 'monthly' 타입으로 고정하거나 지원하도록 업데이트.

## 🎛️ 2. 리스크 관리 UI 개선 (전환 토글 및 날짜 포맷)
- **주간/월간 토글 추가:** FilterBar 상단에 직관적인 버튼형 토글을 배치하여 보기 모드를 쉽게 전환할 수 있도록 했습니다.
- **날짜 표시 최적화:**
  - **월간:** "2026년 03월" 형식으로 연/월 강조.
  - **주간:** "26년 03월 2주차"와 같이 해당 월의 주차 정보를 포함하여 직관성 향상.
- **데이터 중복 제거:** 동일 주차 내에 여러 날짜 데이터가 존재할 경우, 사용자에게는 가장 최근 날짜 하나만 노출되도록 드롭다운 옵션 중복 제거 로직을 적용했습니다.

## 🛠️ 3. 시스템 정합성 확보
- 대시보드의 위험 등급 분포 및 긴급 SKU 카운트, 알림(Alerts) 서비스 등이 새롭게 구분된 리스크 평가 데이터 중 '월간(Monthly)' 기준의 최신 데이터를 우선적으로 참조하도록 수정하여 정보의 혼선을 방지했습니다.
