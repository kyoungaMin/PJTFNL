### 1. ML 파이프라인 전략 수립

#### 배경
대시보드 일부 영역이 ML 결과 테이블(`forecast_result`, `risk_score`, `action_queue`)이 비어 있어 목업 상태로 표시되고 있었음.
ML 팀이 별도로 없어 직접 구현하기로 결정.

#### 선택한 방향
```
Phase 1  Rule-based SQL 함수 (완료) → 목업 → 실데이터 전환
Phase 2  LightGBM ML 파이프라인 고도화 (오늘 작업)
Phase 3  파이프라인 실행 → DB 적재 → 대시보드 자동 전환
```

#### 왜 Prophet 대신 LightGBM을 선택했나?
| 항목 | Prophet | LightGBM |
|------|---------|----------|
| 특징 | 단순 시계열 패턴 학습 | 60개 이상의 복합 피처 학습 가능 |
| 반도체 수요예측 적합성 | 낮음 (계절성 단순 모델) | 높음 (환율, 반도체지수, BOM 원가 등 활용) |
| 팀 기존 코드 | 없음 | `DB/07_pipeline/s4_forecast.py` 이미 구현됨 |
| 결론 | ❌ | ✅ 채택 |

#### 발견: 기존 파이프라인이 이미 완성되어 있었음
`DB/07_pipeline/` 폴더에 다음이 이미 구현되어 있었음:

```
s0_aggregation.py        ← 주별/월별 집계
s1_daily_inventory.py    ← 일간 추정 재고
s2_lead_time.py          ← 리드타임 통계
s3_feature_store.py      ← 피처 엔지니어링 (60개 피처)
s4_forecast.py           ← LightGBM P10/P50/P90 예측 (주간)
s4m_forecast_monthly.py  ← LightGBM 예측 (월간)
s5_risk_score.py         ← 리스크 스코어링

```

**문제**: `feature_store_weekly` 테이블이 비어 있어서 s4가 실행되지 못하는 상태였음.

### 2. ML 파이프라인 정확도 고도화

기존 코드의 한계점을 분석하고 5개 파일을 개선.

#### 개선 전/후 비교

| 항목 | 개선 전 | 개선 후 | 이유 |
|------|---------|---------|------|
| 하이퍼파라미터 탐색 | Grid Search (243 조합 고정) | **Optuna 베이지안 최적화** (100 trial) | 같은 시간에 더 넓은 공간 탐색, 스마트한 탐색 방향 |
| 과적합 방지 | 없음 (고정 n_estimators로만 학습) | **Early Stopping** 전면 적용 | 검증 손실이 나빠지면 자동 중단 |
| 평가 지표 | MAPE만 사용 | **WMAPE 추가** | 소량 제품에서 MAPE가 오차를 과장하는 문제 해결 |
| CV 폴드 수 | 주간 3-fold / 월간 2-fold | **주간 5-fold / 월간 3-fold** | 폴드 수가 적으면 평가 결과가 운에 따라 달라짐 |
| 리스크 등급 | A/B/C/D/F (E 없음) | **A/B/C/D/E/F** | E등급이 없어서 대시보드 "긴급 SKU" KPI가 항상 0이었던 버그 수정 |
| 샘플 제품 수 (튜닝) | 30개 | **50개** | 더 대표성 있는 샘플로 최적 파라미터 탐색 |

### 3. 변경 파일 상세

#### `DB/07_pipeline/ml_utils.py`

**변경 이유**: 모든 ML 모델이 공유하는 공용 유틸리티. 여기서 개선하면 주간/월간 모두 자동 적용.

| 함수 | 변경 내용 |
|------|-----------|
| `compute_metrics()` | WMAPE 계산 추가 |
| `_fit_lgb()` | 신규 — LightGBM 버전(4.x / 구버전) 모두 호환하는 Early Stopping 헬퍼 |
| `walk_forward_cv()` | `early_stopping_rounds` 파라미터 추가, `_fit_lgb` 사용으로 전환 |
| `grid_search_horizon()` | Early Stopping 파라미터 전달 지원 추가 |
| `optuna_search_horizon()` | **신규** — Optuna TPE 베이지안 최적화 (Grid Search 대체) |

**Optuna 탐색 파라미터 (9개):**
```
max_depth, learning_rate, num_leaves, min_child_samples,
reg_alpha (L1 정규화), reg_lambda (L2 정규화),
colsample_bytree, subsample, min_split_gain
```
> Grid Search는 선택한 값들의 조합만 탐색 → Optuna는 연속 공간을 이전 시도 결과를 바탕으로 스마트하게 탐색
