## 2. 새로 만든 파일

### DB/27_email_recipients_ddl.sql
- 이메일 수신자 목록을 저장하는 DB 테이블(`email_report_recipients`) 생성 SQL
- 각 행마다 이메일 주소, 이름, 활성/비활성 상태, 등록 시각을 기록
- ⚠️ Supabase SQL Editor에서 실행 완료 (사용자 직접 실행)

```sql
CREATE TABLE IF NOT EXISTS email_report_recipients (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL DEFAULT '',
  is_active BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### forecastai/src/app/api/admin/email-recipients/route.ts
- 수신자 목록을 읽고, 추가하고, 수정하고, 삭제하는 API (4가지 기능 한 파일에)
  - `GET` : 전체 수신자 목록 조회
  - `POST` : 새 수신자 추가
  - `PATCH` : 활성/비활성 토글
  - `DELETE` : 수신자 삭제

### forecastai/src/app/api/cron/report-email/route.ts
- 매주 월요일 자동 실행되는 임원 보고서 이메일 발송 API
- `GET` : Vercel Cron이 자동 호출 (월요일 오전 9시 KST)
- `POST` : 관리자가 테스트 발송할 때 수동 호출
- 이메일 내용에 포함되는 데이터:
  1. **KPI 6개 카드**: 수주량, 생산량, 수주금액, 재고커버리지, 예측정확도(WMAPE), 미처리발주
  2. **AI 경영 요약**: GPT-4o-mini가 자동 작성
  3. **리스크 등급 분포**: A/B/C/D 등급별 품목 수
  4. **Top 5 위험 품목**: 리스크 점수 상위 5개
  5. **조치 필요 항목**: severity=critical/high인 pending 항목 최대 5개

## 4. 버그 수정

### 버그 1 — 이메일 API 권한 오류 가능성
**파일**: `forecastai/src/app/api/admin/email-recipients/route.ts`

| 수정 전 | 수정 후 |
|---------|---------|
| `supabaseBrowser.auth.getUser(token)` | `supabase.auth.getUser(token)` |

- **원인**: `supabaseBrowser`는 브라우저(클라이언트)용 클라이언트입니다. 서버 API 파일에서 사용하면 인증 토큰 검증이 불안정합니다.
- **해결**: 서버용 클라이언트(`supabase`, service role key 사용)로 교체. 기존 `admin/users` API와 동일한 패턴으로 맞췄습니다.

### 버그 2 — 조치 필요 항목 "없음"으로 나오는 문제
**파일**: `forecastai/src/app/api/cron/report-email/route.ts`, `forecastai/src/app/api/executive-report/route.ts`

| 항목 | 잘못된 컬럼명 | 실제 DB 컬럼명 |
|------|-------------|--------------|
| 우선순위 | `priority` | `severity` |
| 사유 | `reason` | `description` |
| 상태 | `.in('status', ['pending','in_progress'])` | `.eq('status', 'pending')` |

- **원인**: DB 테이블(`action_queue`) 실제 컬럼명과 코드가 맞지 않았습니다. `in_progress` 상태 값도 실제로는 존재하지 않았습니다.
- **해결**: 두 파일 모두 실제 컬럼명으로 수정.

## 8. 이메일 템플릿 개선 (오후 추가 작업)

### 문제 — Gmail에서 내용이 접혀서 보임
발송된 메일을 확인하니 중간중간 "..." 버튼이 생기면서 내용이 숨겨지는 현상이 있었습니다.

**원인**: 이메일 HTML에 `display:grid`, `display:flex` 같은 최신 CSS 레이아웃을 사용했는데, Gmail·Outlook 등 이메일 클라이언트는 이를 무시합니다. 그 결과 내용이 이상하게 쌓이면서 Gmail이 "반복 내용"으로 판단해 자동으로 접어버렸습니다.

**해결**: 이메일 HTML 전체를 `<table>` 기반 레이아웃으로 재작성했습니다. 이메일에서 30년 넘게 안정적으로 사용된 방식입니다.

### 주요 변경 내용

| 항목 | 수정 전 | 수정 후 |
|------|---------|---------|
| KPI 카드 3열 배치 | `display:grid;grid-template-columns:repeat(3,1fr)` | `<table><tr><td width="33%">` |
| AI 요약 2열 배치 | `display:grid;grid-template-columns:1fr 1fr` | 세로 1열로 변경 (박스 3개 순서대로) |
| 특수문자 | `▲ ▼ ·` | `&#9650; &#9660; &middot;` (HTML 엔터티) |
| 전체 구조 | `<div>` 중첩 | `<table>` 중첩 |

### KPI 카드 높이 균일화
같은 행의 카드들이 높이가 달라 보이는 문제도 수정했습니다.
- "전주 대비 ▲92.2%" 줄이 있는 카드만 높이가 더 높아지는 문제
- 해결: 모든 카드에 하단 여백 줄(`&nbsp;`)을 추가해서 높이 통일
