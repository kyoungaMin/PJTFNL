## 6. 추가 작업 — 대시보드 연결 페이지 날짜 기준 통일

### 문제 발견

대시보드에서 KPI 카드를 클릭해 상세 페이지로 이동할 때, 대시보드가 보여주던 날짜 기준과 상세 페이지의 날짜 기준이 다를 수 있는 문제를 확인했습니다.

대시보드는 페이지 진입 시 기준 주차 정보를 `sessionStorage(dashRefWeek)`에 저장합니다.
구매발주·조치큐는 이미 이를 읽어 날짜를 맞추고 있었지만, **재고현황·리스크관리는 연동이 없었습니다.**

### 수정한 파일

**`forecastai/src/components/pages/Inventory.tsx`**
- 페이지 최초 진입 시 `dashRefWeek.yearMonth` 값을 읽어 해당 월의 재고 데이터를 표시
- `yearMonth` 형식 변환: `'2026-02'` → `'202602'` (재고 API 요구 형식)
- `dashRefWeek`가 없으면 기존처럼 최신 월로 자동 fallback

**`forecastai/src/components/pages/RiskManagement.tsx`**
- 필터 날짜 목록을 받아온 후, `dashRefWeek.evalDate`가 목록 안에 있으면 그 날짜를 우선 선택
- `dashRefWeek`가 없거나 해당 날짜 데이터가 없으면 최신 날짜로 자동 fallback

### 결과

| 페이지 | 수정 전 | 수정 후 |
|--------|---------|---------|
| 구매발주 | ✅ 대시보드 기준일 연동 | ✅ 유지 |
| 조치큐 | ✅ 대시보드 기준일 연동 | ✅ 유지 |
| 재고현황 | ❌ 항상 최신 월 표시 | ✅ 대시보드 기준 월 표시 |
| 리스크관리 | ❌ 항상 최신 날짜 표시 | ✅ 대시보드 기준일 표시 |

## 7. 확인 필요 사항 — 리스크관리 기준일이 3/16인 이유 (경아님 검토 필요)

### 현상

리스크관리 페이지의 기준일이 **2026-03-16**으로 표시되고 있습니다.
그런데 실제 수주(주문) 데이터는 **2월 말**까지만 존재합니다.
즉, "3월 16일 기준 리스크"라고 화면에 뜨지만, 실제로는 2월 데이터를 분석한 결과입니다.

### 원인

리스크 점수를 계산하는 파이프라인(s5) 코드를 보면:

```python
# DB/07_pipeline/s5_risk_score.py — 382번째 줄
def run(eval_type):
    results = score_risk(date.today(), eval_type)  # ← 오늘 날짜를 기준일로 저장
```

`date.today()` = **파이프라인을 실행한 날짜**를 기준일로 DB에 저장합니다.
3월 16일에 파이프라인을 실행했으니, 기준일이 3월 16일로 기록된 것입니다.

### 문제점

| 항목 | 실제 값 |
|------|---------|
| 화면에 표시되는 기준일 | 2026-03-16 (파이프라인 실행일) |
| 실제 분석에 사용된 데이터 마지막 날 | 약 2026-02-28 (수주 데이터 마지막 날) |

→ 사용자 입장에서 "3월 데이터를 분석한 건가?" 하고 혼동할 수 있습니다.

### 경아님이 확인해주실 내용

**① Supabase에서 실제 데이터 날짜 확인**

Supabase → SQL Editor에서 아래 쿼리를 실행해주세요:

```sql
-- 1) 리스크 점수 기준일 목록 확인
SELECT eval_date, eval_type, COUNT(*) as cnt
FROM risk_score
GROUP BY eval_date, eval_type
ORDER BY eval_date DESC;

-- 2) 실제 수주 데이터 마지막 날짜 확인
SELECT MAX(order_date) AS last_order_date
FROM daily_order;
```

결과를 보고 두 날짜 차이가 얼마나 되는지 확인합니다.

**② 기준일을 어떻게 표시할지 결정**

아래 두 가지 방향 중 하나를 선택해야 합니다:

| 방향 | 기준일 의미 | 적합한 경우 |
|------|------------|------------|
| **현재 방식** (파이프라인 실행일) | "언제 분석했냐" 기준 | 매일 자동 실행될 경우 큰 문제 없음 |
| **수정 방식** (실제 데이터 마지막 날) | "어느 날짜 데이터를 분석했냐" 기준 | 사용자에게 더 직관적 |

### 수정이 필요하다면

`DB/07_pipeline/s5_risk_score.py` 의 `run()` 함수에서
`date.today()` 대신 `daily_order` 테이블의 `max(order_date)`를 조회해서 eval_date로 사용하면 됩니다.
→ 다솜이 수정 가능, 경아님이 방향 결정 후 요청 주세요.
