```
        ├─ 2순위: 외부 API (Yahoo Finance / FRED / ECOS / 관세청)
        └─ 3순위: MOCK fallback
```

## 의사결정 기록

| 결정 사항 | 선택지 | 결정 | 사유 |
|-----------|--------|------|------|
| API Route 데이터 우선순위 | DB 단독 vs 외부 API 단독 vs 다단계 fallback | 다단계 fallback (DB → 외부 API → MOCK) | DB 미적재 상황에서도 화면 동작, 실데이터 연동 점진적 전환 가능 |
| FastAPI 연동 방식 | 직접 연결 vs 프록시 헬퍼 | `backendClient.ts` 프록시 헬퍼 | `BACKEND_URL` 환경변수 없으면 Supabase 직접 조회 fallback, 개발 환경 분리 용이 |
| 주기 필터 위치 | 별도 탭 vs 기간 필터 옆 버튼 | 기간 필터 옆 버튼 (`FreqFilter`) | 기존 `PeriodFilter`와 통일된 UX, 동일 행에 배치하여 공간 효율적 |
| SOX 실데이터 소스 | Supabase 앵커 데이터 vs Yahoo Finance | Supabase 우선, 없으면 Yahoo Finance | `15_load_realtime_indices.py`가 정기 적재 시 DB 우선 사용, 미적재 시 Yahoo 비공식 API fallback |

## 버그 상세

### Bug 1 — 예측 items 중복 (월간·주간 공통)
- **현상**: `items` 배열에 같은 horizon 값이 4~6회 반복 → KPI 합계 6배 부풀림, 차트 이중 선
- **원인**: `forecast_result` 테이블에 `(product_id, model_id, forecast_date, horizon_days)` 기준 중복 row 존재
- **수정**: `.filter()` + `Set<number>` 로 첫 번째 row만 사용
- **파일**: `forecast-monthly/route.ts`, `forecast-weekly/route.ts`

### Bug 2 — evaluation null 반환
- **현상**: `"evaluation": null` — fallback 값 `{r2: 0.6908, mae: 54.3}` 미적용
- **원인**: Supabase `.single()` 은 row 없을 때 throw 하지 않고 `{data: null, error: PGError}` 반환 → catch 미실행
- **수정**: try-catch 블록 이후 `if (!evaluation) evaluation = { r2: 0.6908, mae: 54.3 }` 추가
- **파일**: `forecast-monthly/route.ts`

### Bug 3 — 고객사 이름 ID로 표시
- **현상**: 고객사 dropdown에 이름 대신 ID 표시 (`{"id":"00108","name":"00108"}`)
- **원인**: `customer.company_name` 컬럼이 DB에 NULL로 저장
- **수정**: `monthly/weekly_customer_summary` 테이블의 `customer_name` 컬럼 직접 사용
- **파일**: `forecast-monthly/customers/route.ts`, `forecast-weekly/customers/route.ts`

### Bug 4 — 실적 히스토리 당월 0건 포함
- **현상**: 차트에 진행 중인 월(예: '26.03, actual=0)이 표시되어 수요 급감처럼 보임
- **수정**: `.filter(r => Number(r.order_qty) > 0)` 추가
- **파일**: `forecast-monthly/route.ts`, `forecast-weekly/route.ts`

### Bug 5 — 고객사 필터 미동작
- **현상**: 고객사 선택 시 `customerItems` 빈 배열 반환

- `customer` 테이블 `company_name` 컬럼은 현재 NULL → summary 테이블의 `customer_name` 사용이 신뢰성 높음
- `useDbSkus` 훅은 DB 로드 실패 시 기존 `SIM_SKUS` 3개로 자동 fallback → 오프라인 환경에서도 화면 동작
