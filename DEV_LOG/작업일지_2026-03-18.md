## 🔧 상세 변경 내역

### 1. Risk API 개선 (`api/risk/route.ts`)

#### 문제
- Supabase는 기본적으로 한 번에 최대 1000행까지만 조회 가능
- 등급 집계(gradeSummary)가 화면에 보이는 200건 기준이어서 실제 전체 건수와 달랐음
- 위험유형 분포(결품/납기/과잉/마진)를 전체 데이터로 계산하는 기능 없었음

#### 해결
- **batchIn 헬퍼**: 400건씩 나눠서 `.in()` 쿼리 → 대량 품목도 전체 조회 가능
- **gradeSummary**: 6개 등급(A~F)을 병렬 COUNT 쿼리로 전체 DB 집계
- **typeSummary (신규)**: 결품/납기/과잉/마진 분포를 전체 기준으로 집계
  - `validProductIds` 있을 때: grade + type 컬럼을 한 번에 조회 (쿼리 절약)
  - 없을 때: 6개 COUNT 쿼리와 type fetchAll을 병렬 실행
- **SKU 단건 조회 (`?sku=` 파라미터)**: 전체 스캔 없이 해당 품목만 즉시 조회
- 모든 응답에 `typeSummary` 포함

#### 변경된 API 응답 구조
```json
{
  "items": [...],
  "evalDate": "2026-03-01",
  "gradeSummary": { "A": 120, "B": 84, "C": 65, "D": 30, "E": 18, "F": 7 },
  "typeSummary":  { "결품": 95, "납기": 48, "과잉": 51, "마진": 130 },
  "totalCount": 324,
  "hasMore": true,
  "source": "database"
}
```

### 2. 재고 API 대시보드 모드 개선 (`api/inventory/route.ts`)

#### 문제
- 대시보드 로딩 시 inventory + product_master + risk_score 등을 15번 이상 DB 왕복 조회
- 응답 시간이 3~5초로 느렸음

#### 해결
- Supabase에 PostgreSQL 집계 함수 3개 등록 (`DB/28_inventory_dashboard_rpc.sql`)
  - `get_inventory_kpi_stats(p_month, p_type)`: 품목유형별 통계 + 카테고리 분포
  - `get_inventory_trend(p_month, p_limit)`: 최근 12개월 재고 추이
  - `get_inventory_avg_coverage(p_month, p_type)`: 평균 커버리지(재고 소진 예상일수)
- 3개의 `supabase.rpc()` 병렬 호출로 대체 → DB 내부에서 계산 후 결과만 반환
- RPC 실패 시 기존 다중 쿼리 방식으로 자동 폴백

**KPI 카드 4종** (전체 기준, 정확한 수치)
| 카드 | 기준 | 색상 |
|------|------|------|
| 즉시 조치 필요 (E·F 등급) | gradeSummary 전체 기준 | 빨강 |
| 주의 필요 (D 등급) | gradeSummary 전체 기준 | 주황 |

| 미처리 건수 (E·F 중) | 로드된 items 기준 | 파랑 |

> **주의**: 기존에 "결품 위험"이라고 표시하던 카드가 로드된 200건 기준으로 잘못 집계되던 문제를 "전체 관리 품목(totalCount)"으로 교체하여 수정

**2-컬럼 시각화 섹션**
- 왼쪽: 등급별 현황 (클릭 시 필터) + 범례 + 위험유형 분포 막대
- 오른쪽: 즉시 조치 필요 TOP 5 (클릭 시 드로어)

## ✅ 기술적 판단 기록

### Supabase 1000행 제한 해소 방법
PostgREST(Supabase REST API)는 한 번 요청에 기본 최대 1000행을 반환.
→ `fetchAll()`: offset을 1000씩 올려가며 빈 응답이 올 때까지 반복 조회
→ `batchIn()`: 조건 목록(ID 등)이 많을 때 400개씩 나눠 `.in()` 쿼리 실행

### gradeSummary vs typeSummary 집계 방식 차이
- **gradeSummary**: `risk_grade` 컬럼이 DB에 저장되어 있어 6개 COUNT 쿼리로 빠르게 집계 가능
- **typeSummary**: 위험유형은 DB에 별도 컬럼 없음. `stockout_risk`, `excess_risk`, `delivery_risk`, `margin_risk` 4개 값 중 가장 큰 것을 TypeScript로 판별(`dominantType()`)
  → 전체 rows의 4개 컬럼을 서버에서 읽어 집계 후 반환

### KPI 카드 중복 문제 수정
이전: 즉시조치(E+F) + 주의(D) + **위험합계(D+E+F)** = 세 번째 카드가 첫 번째+두 번째의 합 → 의미 중복
현재: 즉시조치(E+F) + 주의(D) + **전체관리품목** + 미처리(E+F 중) → 4개 카드 모두 독립적 지표
