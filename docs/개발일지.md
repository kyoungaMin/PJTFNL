### 재고 현황 페이지 UI 개선 (`Inventory.tsx`)

**문제 및 요구사항**
- 년월 선택 후 데이터 조회 중 MonthPicker(조회년월)가 사라지는 버그
- 품목 유형 선택 방식이 탭 버튼으로 화면 공간을 과다 차지
- 조회조건 배치가 상·하단으로 분리되어 있지 않아 사용성 저하
- 하단 SKU 목록 필터가 토글 버튼 방식이어서 일관성 부족

**변경 내용**
1. **조회년월 사라짐 버그 수정**
   - 기존: `!dashLoading && availableMonths.length > 0` 조건으로 로딩 중 MonthPicker 숨김
   - 수정: `availableMonths.length > 0` 조건만 유지 → 데이터 조회 중에도 선택한 년월 표시
   - 로딩 중이고 월 목록이 아직 없을 때는 "조회 중…" placeholder 표시

2. **품목유형 탭 → 드롭다운(Select) 전환**
   - 기존: 유형별 탭 버튼 row (전체/제품/반제품/부재료/소모품/원재료/자산)
   - 수정: 헤더 우측 조회조건 영역에 Select 드롭다운으로 통합

3. **상단 조회조건 정렬** (헤더 우측)
   - 조회년월(MonthPicker) + 품목유형(Select) 나란히 배치

4. **하단 SKU 목록 조회조건 드롭다운 전환**
   - 기존: 상태 토글 버튼 + 검색 + 카테고리 버튼
   - 수정: 품목유형 Select → SKU/품목명 검색 → 상태 Select(건수 포함) 순으로 통일
   - 미사용 `cats` (카테고리 목록) useMemo 제거

## 2026-03-10 | KoraenDavid

### 재고 현황 페이지 실DB 연동 및 UX 개선

**배경**
- Inventory 페이지가 Mock 데이터(`INV_ITEMS`, `INV_TREND`)를 사용하고 있어 실운영 불가
- 초기 로드 시 전체 SKU(~2,000건) 조회로 페이지 진입이 느림

**신규 API: `/api/inventory`**
- **대시보드 모드** (기본): KPI + 월별 추이 + 유형별 통계 → 빠른 초기 로드
- **목록 모드** (`mode=list`): SKU 상세 목록 200건씩 페이지네이션
- Supabase 1,000행 기본 limit 우회: `fetchAll()` 페이지네이션 헬퍼, `batchIn()` 청크 처리
- 가용 스냅샷 월 24개월 자동 탐색 (cursor-based)
- Promise.all() 병렬 쿼리로 성능 최적화

**프론트엔드 개선**
- 대시보드 KPI·차트는 진입 즉시 로드 (`dashLoading`)
- SKU 목록은 월 확정 후 자동 로드 (`listLoading`)
- "펼쳐보기" 50건씩 클라이언트 확장 + "더 보기" DB 추가 조회
- MonthPicker 컴포넌트: 연도 네비게이션 + 월 그리드 (가용 월만 활성화)
- 실DB 제품유형 값 매핑: 제품/반제품/원재료/부재료/소모품/자산

## 주요 기술 결정 사항

| 항목 | 결정 | 이유 |
|------|------|------|
| Supabase 1,000행 limit 우회 | `fetchAll()` 페이지네이션 + RPC | REST 기본 limit으로 집계 오류 발생 |
| 재고 API 모드 분리 | dashboard / list 모드 | 초기 로드 속도 vs 상세 데이터 필요 시점 분리 |
| 제품유형 필터 위치 | 헤더 우측 드롭다운 | 전체 페이지 맥락에서 최우선 조회 조건 |
| SKU 목록 페이지네이션 | 클라이언트 50건 펼치기 + DB 200건 추가 | 렌더 비용 최소화 |
