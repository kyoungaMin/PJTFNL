### 2. 버그 수정 (5건)

#### Bug 1 — 예측 데이터 중복 (주간·월간 공통)
- **원인:** `forecast_result` 테이블에 동일 `(product_id, model_id, forecast_date, horizon_days)` 행이 복수 존재
- **증상:** 월간 items 3개여야 하는데 15개 반환, 주간도 W1이 15회 중복
- **수정:** `horizon_days` 기준 `Set<number>`로 중복 제거
- **파일:** `forecast-monthly/route.ts`, `forecast-weekly/route.ts`

#### Bug 2 — evaluation null 반환
- **원인:** Supabase `.single()` 은 row 없을 때 throw 하지 않고 `{data:null, error:...}` 반환 → catch 블록 미실행
- **증상:** `"evaluation": null` (fallback 값 미적용)
- **수정:** try-catch 이후 `if (!evaluation) evaluation = { r2: 0.6908, mae: 54.3 }` 추가
- **파일:** `forecast-monthly/route.ts`

#### Bug 3 — 고객사 이름 미조회
- **원인:** `customer.company_name` 컬럼이 DB에서 NULL → 고객사명 대신 ID가 표시됨
- **수정:** `monthly_customer_summary.customer_name`, `weekly_customer_summary.customer_name` 직접 사용 (customer 테이블 조인 제거)
- **파일:** `forecast-monthly/customers/route.ts`, `forecast-weekly/customers/route.ts`

#### Bug 4 — 실적 히스토리에 당월(0건) 포함
- **원인:** 진행 중인 월(예: 2026-03)이 `order_qty = 0`으로 조회되어 차트에 표시
- **수정:** `.filter(r => Number(r.order_qty) > 0)` 추가
- **파일:** `forecast-monthly/route.ts`, `forecast-weekly/route.ts`

#### Bug 5 — 고객사 필터 오동작
- **원인:** 고객사 필터를 `customer_name` 문자열로 비교 → 이름 불일치 시 결과 없음
- **수정:** `customer_id` 기준으로 필터링 변경
- **파일:** `forecast-monthly/route.ts`

### 3. 수요예측 화면 DB 연결

#### 문제
- 주간·월간 예측 화면 모두 기본 SKU(`00001-A010174`)에 예측 데이터 없음 → MOCK 표시
- SKU 목록이 하드코딩(3개) → 실제 DB SKU 불표시

#### 해결
- **`/api/forecast-skus`** 신규 API: `forecast_result`에서 예측 데이터 보유 SKU를 동적 조회 후 `product_master`에서 이름·규격 매핑
- **`useDbSkus` 훅** 추가 (WeeklyForecast, MonthlyForecast 각각):
  - `/api/forecast-skus?model=weekly|monthly` 호출
  - 실패 시 기존 `SIM_SKUS` 폴백
  - 로드 완료 시 첫 번째 DB SKU 자동 선택
- **파일:** `WeeklyForecast.tsx`, `MonthlyForecast.tsx`
